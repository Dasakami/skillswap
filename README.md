# SkillSwap — обмен навыками между студентами

Django 5 + Django REST Framework + SQLite. Фронтенд (HTML, CSS и vanilla JS) раздаётся тем же Django-сервером, поэтому API и интерфейс работают с одного адреса без Docker, PostgreSQL и настройки CORS.

## Локальный запуск на Windows

В первом терминале из корня проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 127.0.0.1:8000
```

Откройте <http://127.0.0.1:8000>. Интерфейс использует API на том же сервере по адресу `/api`.

Во втором терминале можно выполнить автотесты (Django создаст для них отдельную временную SQLite-базу, демо-данные из `db.sqlite3` не затрагиваются):

```powershell
.\.venv\Scripts\Activate.ps1
python manage.py test
```

Если демо-данные уже созданы, повторный `seed_demo` намеренно завершится сообщением об этом. Для полного сброса локальной базы и повторного наполнения используйте `python manage.py flush --no-input`, затем `python manage.py seed_demo`.

На macOS/Linux активируйте окружение командой `source .venv/bin/activate`; остальные команды те же. SQLite-файл по умолчанию — `db.sqlite3` в корне проекта. При необходимости путь можно задать переменной `SQLITE_DB_PATH`.

## Docker

`docker-compose.yml` сохранён как прежняя заготовка окружения. Приложение сейчас настроено на SQLite; compose не нужен и Django к запущенному в нём PostgreSQL не подключается.

## API (префикс `/api`, JSON, заголовок `Authorization: Token <token>`)

| Метод и путь | Доступ | Описание |
|---|---|---|
| POST `/auth/register`, `/auth/login`, `/auth/logout` | все / авторизованный | токен; роль при регистрации всегда «участник» |
| GET, PATCH `/me` | авторизованный | свой профиль |
| GET `/users/{id}` | все | профиль, предложения, отзывы; `contact` — только владельцу и подтверждённому партнёру |
| GET `/categories` | все | справочник |
| GET `/offers?q=&category=&level=&format=&author=&ordering=&page=` | все | каталог (только активные) |
| POST `/offers` | участник | создание, можно сразу со `slots: [{start_at, end_at}]` |
| GET `/offers/{id}` · PATCH `/offers/{id}` | все · автор | карточка · редактирование |
| POST `/offers/{id}/archive` · `/offers/{id}/slots` | автор | архив · добавить слот |
| GET `/offers/mine` · `/offers/favorites` | авторизованный | мои · избранное |
| POST/DELETE `/offers/{id}/favorite` | авторизованный | избранное (чужие предложения) |
| POST `/offers/{id}/report` | авторизованный | жалоба |
| POST `/slots/{id}/requests` | авторизованный | заявка на слот |
| GET `/requests?box=incoming\|outgoing&status=` · GET `/requests/{id}` | участники заявки | список / детали |
| POST `/requests/{id}/accept\|reject\|cancel\|complete` | см. ниже | смена статуса |
| GET/POST `/requests/{id}/messages` | участники принятой/завершённой встречи | чат (обычный HTTP) |
| POST `/requests/{id}/review` | ученик завершённой встречи | `{score: 1..5, text}` |
| GET `/moderation/reports` · POST `/moderation/reports/{id}/resolve` | модератор | `{action: hide\|dismiss, reason}` |
| POST `/moderation/offers/{id}/hide\|unhide` | модератор | скрыть / вернуть |

**Коды ошибок:** 400 — ошибки ввода (`{"detail": "...", "errors": {"поле": ["..."]}}`), 401 — нет входа, 403 — нет прав, 404 — не найдено (скрытые предложения для посторонних тоже 404), 409 — конфликт состояния. В `detail` всегда человекочитаемая причина.

## Статусы заявки

```
pending ──accept (автор)──► accepted ──complete (автор, после начала слота)──► completed
   │ ├─reject (автор)──► rejected              │
   │ └─cancel (ученик)─► cancelled ◄─cancel (любой участник, до начала)
```
Принятие атомарно: блокируется слот, остальные `pending` на этот слот автоматически становятся `rejected`. Вторая принятая заявка на слот невозможна и на уровне БД (частичный уникальный индекс). Подробности — `docs/ER.md`.

## Сценарий проверки на защите

1. Войти как `anna` → «Мои предложения» → создать предложение со слотом.
2. В другом браузере (или режиме инкогнито) войти как `egor` → записаться на слот.
3. `anna` → «Мои встречи» → «Принять» → обмен сообщениями в «Чате».
4. **Завершить встречу можно только после начала слота.** Для живой демонстрации создай слот на ближайшие 1–2 минуты (поле datetime-local), подожди и нажми «Завершить». Готовые примеры в демо-данных: `anna` (ученица) была на занятии у `boris` — встреча завершена, отзыв оставлен; `boris` (ученик) был у `vera` — встреча завершена, отзыва нет, поэтому под `boris` можно показать форму отзыва и отказ при повторной отправке.
5. Права: посторонний (`dina`) на `GET /api/requests/{id}/messages` получает 403; контакт `anna` на её странице виден только `boris` (партнёр) и ей самой.
6. Модерация: `dina` подала жалобу → войти как `moderator` → «Модерация» → скрыть с причиной → предложение пропало из каталога.

## Структура

```
config/            настройки Django (БД — через переменные окружения)
swap/models.py     модели и ограничения БД
swap/services.py   бизнес-правила и переходы статусов (транзакции, блокировки)
swap/serializers.py, views.py, urls.py, permissions.py, exceptions.py
swap/tests.py      автотесты по критериям приёмки
swap/management/commands/seed_demo.py
frontend/          index.html + static/app.js, style.css
docs/ER.md         ER-диаграмма (Mermaid) и обоснование изменений
```
